# Feature Specification: 个人中心头像自动补抓

**Created**: 2026-07-12
**Status**: Draft
**Input**: "登入过程中可能会抓不到我自己的头像，在我每次选择「我的」界面时检查一下，如果抓不到就重新抓一次"

## Overview

用户在登录 Pixiv 后，由于登录过程中的 WebView 页面加载状态不稳定，有时无法从 DOM 中提取到头像 URL，导致「我的」页面一直显示默认占位头像。本功能在用户每次切换到「我的」标签页时，自动检查头像是否已成功缓存到本地；若未缓存，则通过 Pixiv API 重新获取用户资料并下载头像，确保用户在已登录状态下始终能看到自己的头像。

## User Scenarios & Testing

### User Story 1 - 已登录用户进入「我的」页面自动补抓头像 (Priority: P1)

已登录但头像未成功缓存的用户，切换到「我的」标签页时，系统自动检测到本地无头像缓存，通过 API 获取用户资料并下载头像到本地，页面显示用户头像。

**为什么是 P1**: 这是用户最常遇到的核心体验问题 — 登录后看不到自己头像，直接影响用户对应用完整性的感知。

**独立测试**: 可单独验证：模拟登录但清除本地头像缓存 → 切换到「我的」标签 → 确认头像自动加载完成。

**验收场景**:

1. **Given** 用户已登录但本地无头像缓存文件（avatar_{userId}.jpg 不存在），**When** 用户切换到「我的」标签页，**Then** 系统自动调用 Pixiv API 获取用户资料头像 URL，下载并缓存到本地，页面上显示用户头像而非默认占位图。

2. **Given** 用户已登录且本地已有头像缓存文件，**When** 用户切换到「我的」标签页，**Then** 系统检测到本地缓存存在，不触发额外网络请求，直接显示本地头像。

3. **Given** 用户已登录但网络不可用，且本地无头像缓存，**When** 用户切换到「我的」标签页，**Then** 系统尝试通过 API 获取头像但因网络失败，页面继续显示默认占位图，不崩溃、不报错。

---

### User Story 2 - 重新登录后头像自动补抓 (Priority: P2)

用户退出登录后重新登录（或 token 刷新后），进入「我的」标签页时自动补抓头像。

**为什么是 P2**: 重新登录场景也是头像丢失的高发场景，但出现的频率低于首次登录。

**独立测试**: 登录后清除本地头像缓存 → 退出登录 → 重新登录 → 切换至「我的」标签 → 确认头像加载。

**验收场景**:

1. **Given** 用户刚完成重新登录且本地无对应 userId 的头像缓存，**When** 用户首次切换到「我的」标签页，**Then** 系统自动补抓并缓存头像。

---

### Edge Cases

- 网络请求超时或失败：不阻塞页面渲染，保留占位图，下次进入「我的」页面时自动重试。
- 用户未登录：不执行任何检查或网络请求。
- Pixiv API 返回的用户资料中不含头像字段：保留占位图，不做额外处理。
- 头像下载过程中用户切换到其他标签页：下载在后台继续完成，下次切换到「我的」时直接使用缓存文件。

## Requirements

### Functional Requirements

- **FR-001**: 系统必须在「我的」页面（SettingPage）每次 `aboutToAppear` 触发时，检查当前登录用户的本地头像缓存文件是否存在。
- **FR-002**: 若本地头像缓存文件不存在，系统必须自动调用 `AppState.refreshUserInfo()` 方法，通过 Pixiv API 获取用户最新头像 URL。
- **FR-003**: 获取到有效的头像 URL 后，系统必须自动下载头像并缓存到本地文件系统。
- **FR-004**: 缓存完成后，系统必须自动更新 UI 显示本地缓存头像，而非默认占位图。
- **FR-005**: 若网络请求失败或 API 返回不含头像字段，系统必须保持当前显示（占位图），不抛出异常或导致页面崩溃。
- **FR-006**: 用户未登录状态下，系统不得发起任何网络请求。

### Key Entities

- **本地头像缓存文件**: 存储在 `{cacheDir}/avatar_{userId}.jpg`，用户唯一头像的本地持久化副本。
- **CookieStorage (pixiv_avatar_url)**: 持久化存储的头像远程 URL，作为 `cacheAvatar()` 的下载源。若此值为空，`refreshUserInfo()` 可通过 API 重新获取。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 已登录用户在切换到「我的」标签页后 3 秒内，头像自动完成加载显示（如有可用网络）。
- **SC-002**: 头像缺失场景下（模拟清除本地缓存），上述自动补抓流程 100% 触发，且不产生应用崩溃。
- **SC-003**: 无网络环境下切换到「我的」页面，应用不崩溃，不显示错误弹窗，保持占位图正常显示。

## Assumptions

- 用户使用 Pixiv OAuth 登录，有有效的 access_token 用于 API 请求。
- 本地文件系统（应用沙箱目录）可用，有足够的空间写入头像缓存文件。
- 头像 URL 从 Pixiv API 的 `UserInfoResponse.body.image` 字段获取。
- 检查头像是否存在的方法与现有 `SettingPage.getAvatarUrl()` 逻辑一致（通过 `fileIo.openSync` 探测本地文件）。

## Open Questions

- 是否需要加入重试上限（例如连续 N 次失败后停止自动重试）？当前实现无上限约束，每次切换到「我的」页面都会尝试。
